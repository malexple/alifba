## Имя языка: **Älifba** (Алифба)

«Алифба» — это название алфавита во всех тюркских языках (от «алиф» + «ба» — первые буквы арабской азбуки). Подходит идеально: это язык, построенный на буквах и их гармонии.

Внутреннее расширение файла: `.alf` Исполняемый файл: `ALF.COM` — 4 КБ в памяти, работает под DOS/FreeDOS.

### Зачем нам мягкая форма и твердая форма?

Наличие двух форм (твердой и мягкой) для каждого суффикса — это **не усложнение, а главная техническая фича**, которая решает сразу три важнейшие задачи в условиях жесткого лимита памяти в 4 Кб.

Вот зачем компилятору и программисту нужны обе формы:

**1. Автоматический контроль типов данных (Без лишнего кода)**

Типы переменных определяются по гласным буквам («твердые» переменные = числа, «мягкие» = строки), суффикс служит **индикатором типа для компилятора**.

- Когда парсер видит код `age >= 18sa`, твердый суффикс `-sa` сразу говорит ему: *«Работай с регистрами процессора `AX/BX` как с числами»*.
- Если бы код был `name == "Airat"se`, мягкий суффикс `-se` мгновенно скомандовал бы: *«Включи побайтовое сравнение строк в памяти через инструкцию `CMPSB`»*.

Если бы форма была всего одна (например, только `-sa`), нам пришлось бы тратить драгоценную память на хранение таблицы типов для каждой переменной, чтобы компилятор знал, где число, а где строка.

**2. Сжатие кода в 1 байт (Токенизация)**

Для экономии места на флоппи-диске и в ОЗУ компилятор на ассемблере x86 превращает суффиксы в битовые маски. Нам не нужно хранить в памяти буквы `s-a` или `s-e`.

Мягкость и твердость кодируются **всего одним битом** внутри байт-кода операции:

- `0x05` (в бинарном виде `00000101`) — суффикс `-sa` (флаг твердости `1` в конце).
- `0x04` (в бинарном виде `00000100`) — суффикс `-se` (флаг мягкости `0` в конце).

Процессор виртуальной машины считывает этот байт, мгновенно видит последний бит и понимает, с какими данными (двоичными или текстовыми) ему предстоит работать.

**3. Лингвистическая эргономика (Удобство чтения)**

Если оставить только одну форму, язык потеряет свою гармонию, и код станет тяжело читать и произносить вслух (даже про себя).

- Словосочетание `file-ka` (мягкий корень + твердый суффикс) звучит неестественно и «режет слух».
- Вариант `file-ke` или `port-ka` звучит гармонично.

Так как мы пишем язык, вдохновленный татарской грамматикой, сохранение сингармонизма делает код красивым, структурированным и приятным для написания.



### Как выглядит готовый код программ 

Поскольку суффикс **`-saga`** (твердый) и **`-sege`** (мягкий) дословно переводится как *«если [равно], то [направить туда]»*, код пишется в строгом порядке: **`Объект -> Значение-суффикс -> Цель`**.

Пример 1: Проверка порта (Твердая гармония)

- **Код:** `port 255saga quit`
- **Как читается человеком:** «Порт, если равен 255, то на выход».
- **Как работает компилятор:** Видит твердое имя `port` (число) и проверяет суффикс `-saga`.

Пример 2: Проверка клавиши (Мягкая гармония)

- **Код:** `key 'q'sege quit`
- **Как читается человеком:** «Клавиша, если равна 'q', то на выход».
- **Как работает компилятор:** Видит мягкое имя `key` (строка/символ) и проверяет суффикс `-sege`.

Пример 3: Логика «Иначе» (Аналог ELSE)

В таком синтаксисе `ELSE` реализуется за счет естественного линейного выполнения кода в DOS (как в ассемблере). Если условие сработало — программа улетает по метке. Если не сработало — процессор просто идет на следующую строчку.

text

```
status 1saga active   // Если статус 1, прыгаем на метку 'active'
"Error!" printka      // (Это выполнится, ТОЛЬКО если статус НЕ 1)
quitga                // Уходим на выход, чтобы не зайти в блок active

active:
"Success!" printka
```



------

Как это сжимается в памяти (Магия 4-х байт)

Когда вы компилируете этот код внутри DOS, строка `port 255saga quit` превращается в ультра-компактный бинарный массив всего из **4 байт**:

| Байт         | Что внутри (Данные)             | Роль для процессора x86                     |
| ------------ | ------------------------------- | ------------------------------------------- |
| **1-й байт** | `0x12` (например)               | Токен-номер переменной `port`               |
| **2-й байт** | `0xFF` (число 255)              | Значение для сравнения                      |
| **3-й байт** | `0x0A` (Токен суффикса `-saga`) | Команда ассемблеру: «Сравни 1-й и 2-й байт» |
| **4-й байт** | `0x20` (например)               | Адрес смещения (куда прыгать, если `TRUE`)  |

------

Как написать обработчик этого суффикса на ассемблере x86

Внутри вашего `.COM` файла интерпретатора (который вы пишете на ассемблере) выполнение этого суффикса займет всего **5 строк машинного кода**:

assembly

```
; Предположим, AL = значение переменной port, BL = число 255, DX = адрес 'quit'
CMP AL, BL       ; Шаг 1: Сравниваем значение с константой
JNE next_line    ; Шаг 2: Если НЕ равно (FALSE), просто игнорируем и идем дальше
JMP DX           ; Шаг 3: Если РАВНО (TRUE), мгновенно прыгаем на адрес 'quit'
next_line:
; продолжаем выполнение программы...
```

Этот ассемблерный код выполнится за наносекунды. Ему не нужно держать в памяти дерево абстрактного синтаксиса, выделять ОЗУ под скобки или высчитывать приоритеты операторов.



## Тип 1. Условно-Направительный суффикс кода (Прыжок по условию)

Это суффиксы **`-saga`** (твердый) и **`-sege`** (мягкий).

- **Грамматический смысл:** *«Если [равно], то [направить выполнение к...]»*.
- **Что заменяет:** Целую конструкцию `IF variable == value THEN GOTO label`.

Примеры использования:

text

```
// Твердая гармония: 'port' (число) -> суффикс '-saga'
port 255saga exit

// Мягкая гармония: 'key' (символ) -> суффикс '-sege'
key 'q'sege exit
```

Используйте код с осторожностью.



------

Тип 2. Условно-Направительный суффикс данных (Вывод по условию)

А что, если нам нужно не прыгать по коду, а **вывести данные** (на экран или в порт), но только если условие выполнено? Для этого мы скрещиваем условие с направительным падежом данных (`-ka/-ke`).

Мы получаем суффиксы **`-saka`** (твердый) и **`-seke`** (мягкий).

- **Грамматический смысл:** *«Если [равно], то [направить данные в...]»*.
- **Что заменяет:** Конструкцию `IF variable == value THEN PRINT "текст"` или `POKE`.

Примеры использования:

text

```
// 1. Условный вывод на экран (Мягкая гармония)
// "Если нажатая клавиша (key) равна 'e', направить строку 'Error' на экран"
key 'e'seke "Error!"

// 2. Условная запись в порт DOS (Твердая гармония)
// "Если сигнал (signal) равен 1, направить байт 0xAA в порт"
signal 1saka 0xAA
```

Сводная таблица сложных слитных суффиксов

| Название операции                | Твёрдая форма | Мягкая форма | Что делает внутри процессора x86 (DOS)                       | Пример кода                                                  |
| -------------------------------- | ------------- | ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **Условие + Переход (GOTO)**     | **-saga**     | **-sege**    | Сравнивает. Если `ИСТИНА`, меняет указатель инструкций `IP` на адрес метки. | `port 0saga loop`   *(Если порт 0, на 'loop')*               |
| **Условие + Вывод (PRINT/POKE)** | **-saka**     | **-seke**    | Сравнивает. Если `ИСТИНА`, копирует следующее значение в буфер экрана/порта. | `key 's'seke "Start"`   *(Если нажата 's', вывести "Start")* |

------

Почему это идеальное комбо для 4 Кб памяти?

1. **Никаких промежуточных состояний:** В обычном языке процессор тратит время и память: сначала вычисляет условие, кладет `true/false` в стек, затем инструкция `IF` стягивает это значение из стека и думает, куда прыгнуть. У нас суффиксы `-saga` и `-saka` выполняют сравнение и действие **за один проход процессора**.
2. **Экономия на токенах:** Для компилятора суффикс `-saga` — это всего **1 байт** (например, `0x1A`), а суффикс `-saka` — другой байт (например, `0x1B`). Программа превращается в плоскую, невероятно короткую последовательность байт-кодов



## Тип 2.  условно-исходных суффиксов

 Скрещивание **условного** (`-sa/-se`) и **исходного** (`-dan/-den`) суффиксов рождает потрясающую по своей лаконичности конструкцию — **условно-исходный суффикс**.

Если направительный суффикс (`-saga/-saka`) отвечает на вопрос *«если да, то куда отправить?»*, то исходный суффикс отвечает на вопрос: **«если да, то откуда взять (считать) новые данные?»**.

В ASCII-латинице мы получаем суффиксы **`-sadan`** (твердый) и **`-seden`** (мягкий).

- **Грамматический смысл:** *«Если [условие верно], то [взять (прочитать) значение из...]»*.
- **Что заменяет в Basic / Си:** Конструкцию `IF variable == value THEN data = PEEK(address)` или чтение из порта/файла по условию.

------

**Примеры использования условно-исходных суффиксов**

**Пример 1: Условное чтение из памяти DOS (Твердая гармония)**

Допустим, у нас есть переменная `status` (твердое имя, число). Если статус равен `1`, нам нужно считать байт из видеопамяти по адресу `47104` (чтобы проверить, какой символ горит на экране).

**Код на нашем языке:**

text

```
status 1sadan 47104
```



- **Как читается человеком:** «Статус, если равен 1, то считать данные **ИЗ** адреса 47104».
- **Результат операции:** Если статус равен 1, новое считанное число автоматически падает на вершину стека (или записывается в регистр). Если статус не равен 1, команда чтения игнорируется.

**Пример 2: Условный опрос порта клавиатуры (Мягкая гармония)**

У нас есть текстовая/байтовая переменная `pipe` (мягкое имя). Если в `pipe` пришел маркер готовности `'R'` (Ready), нам нужно считать сам символ **ИЗ** порта ввода клавиатуры (например, порт `0x60` — в десятичной системе `96`).

**Код на нашем языке:**

```
pipe 'R'seden 96
```

- **Как читается человеком:** «Пайп, если равен 'R', то считать байт **ИЗ** порта 96».

| Название операции     | Твёрдая форма | Мягкая форма | Смысл операции (для 4 Кб DOS)                                | Пример кода           |
| --------------------- | ------------- | ------------ | ------------------------------------------------------------ | --------------------- |
| **Условие + Переход** | **-saga**     | **-sege**    | Если истина \(\rightarrow \) прыгнуть на метку (`GOTO`)      | `port 0saga loop`     |
| **Условие + Вывод**   | **-saka**     | **-seke**    | Если истина \(\rightarrow \) записать/напечатать (`POKE/PRINT`) | `key 's'seke "Go"`    |
| **Условие + Ввод**    | **-sadan**    | **-seden**   | Если истина \(\rightarrow \) считать/прочитать (`PEEK/IN`)   | `status 1sadan 47104` |

------

Как это устроено в байт-коде и ассемблере x86

Для компилятора суффикс `-sadan` — это снова всего **1 байт** (например, токен `0x1C`).

Когда интерпретатор на ассемблере встречает этот токен, он выполняет ультра-короткую процедуру:

assembly

```
; Предположим, AL = переменная status, BL = 1, DX = адрес памяти 47104
CMP AL, BL       ; 1. Проверяем условие (status == 1)
JNE next_cmd     ; 2. Если ложно, пропускаем чтение
MOV SI, DX       ; 3. Если истинно, берем адрес 47104
MOV AL, [SI]     ; 4. Считываем байт из памяти прямо в регистр (или стек)
next_cmd:
```



В чем гениальность подхода?

В классическом Basic пришлось бы писать: `IF S = 1 THEN X = PEEK(47104)`. Парсеру нужно обработать имя переменной `X`, знак `=`, слово `PEEK` и скобки.
В нашем англо-татарском концепте **переменная для записи не нужна** — данные из исходного падежа (`-sadan`) автоматически падают на вершину виртуального стека. Код сократился в 3 раза, а парсер на ассемблере стал еще проще!



Тип 3. **условного** + **отрицательного** + **направительного** суфиксов

Скрещивание **отрицательного** (`-mas/-mes`), **условного** (`-sa/-se`) и **направительного** (`-ka/-ke` или `-ga/-ge`) суффиксов дает нам мощнейший инструмент: **условно-отрицательно-направительный суффикс**.

Если прошлые суффиксы срабатывали по принципу *«если РАВНО, то...»*, то эти работают в режиме **«если НЕ РАВНО, то...»** (аналог `IF NOT` или `if variable != value`).

В нашей латинизированной ASCII-системе мы получаем две группы слитных суффиксов:

1. **`-masaga` / `-mesege`** — Если **НЕ** равно, то **прыгнуть** (Переход).
2. **`-masaka` / `-meseke`** — Если **НЕ** равно, то **вывести** (Запись данных).

------

Примеры использования

Пример 1: Условное отрицание + Переход (`-masaga` / `-mesege`)

Допустим, мы пишем игровой цикл в DOS. Переменная `key` (мягкое имя, символ клавиатуры) постоянно опрашивается. Если нажата **НЕ** клавиша `'q'`, игра должна продолжаться и прыгать на метку `loop`.

**Код на нашем языке:**

text

```
key 'q'mesege loop
```



- **Как читается человеком:** «Клавиша, если **не** равна 'q', то направить выполнение к `loop`».
- **Что заменяет в Basic:** `IF key <> "q" THEN GOTO loop`.

Пример 2: Условное отрицание + Вывод (`-masaka` / `-meseke`)

У нас есть числовая переменная `port` (твердое имя). Мы ждем от устройства сигнал готовности — число `1`. Если пришло любое другое число (сигнал **не** равен 1), нам нужно мгновенно отправить в буфер экрана строку `"Wait"`.

**Код на нашем языке:**

text

```
port 1masaka "Wait"
```

Используйте код с осторожностью.



- **Как читается человеком:** «Порт, если **не** равен 1, то направить строку "Wait" на экран».
- **Что заменяет в Си:** `if (port != 1) { print("Wait"); }`.

| Действие               | Если РАВНО (Твердое / Мягкое) | Если НЕ РАВНО (Твердое / Мягкое) | Операция в DOS / x86                                       |
| ---------------------- | ----------------------------- | -------------------------------- | ---------------------------------------------------------- |
| **Переход (GOTO)**     | **-saga** / **-sege**         | **-masaga** / **-mesege**        | Проверка флагов процессора \(\rightarrow \) `JE` или `JNE` |
| **Вывод (PRINT/POKE)** | **-saka** / **-seke**         | **-masaka** / **-meseke**        | Копирование данных в экран/порт по условию                 |
| **Ввод (PEEK/IN)**     | **-sadan** / **-seden**       | **-masadan** / **-meseden**      | Чтение данных из памяти/порта по условию                   |

------

Как это экономит память в коде интерпретатора на ассемблере x86

Для обычного парсера обработка `!=` или `NOT` — это головная боль: нужно менять логику вычисления всего выражения.

В нашем случае суффикс `-masaga` компилируется в **1 байт** (например, токен `0x2A`). Когда ассемблерный движок DOS видит его, он выполняет ту же самую процедуру сравнения, меняя всего **одну машинную инструкцию** прыжка (`JNE` вместо `JE`):

assembly

```
; Обработка токена 0x2A (-masaga). AL = key, BL = 'q', DX = адрес 'loop'
CMP AL, BL       ; 1. Сравниваем значения
JE skip_jump     ; 2. ЕСЛИ РАВНЫ — пропускаем прыжок (так как у нас ОТРИЦАНИЕ)
JMP DX           ; 3. ЕСЛИ НЕ РАВНЫ — улетаем на метку 'loop'
skip_jump:
```

Используйте код с осторожностью.



Код интерпретатора на ассемблере для обработки отрицания не увеличился ни на один байт — мы просто повторно используем ту же функцию сравнения, но инвертируем условие прыжка.



## Валидация сингармонизма

В выражении `port 1masaka "Wait"` сталкиваются **два разных контекста**:

1. **Входной контекст (Сравнение):** Мы проверяем переменную `port` и число `1`. Это абсолютно **твердый** контекст (`port` — число, гласная `O`).
2. **Выходной контекст (Действие):** Мы выводим строку `"Wait"`. Строка — это по нашему правилу типов абсолютно **мягкий** контекст (гласная `A` отсутствует, есть мягкие гласные или ASCII-текст).

Именно поэтому вариант `port 1masеka` кажется вам интуитивно более правильным (или наоборот, ошибочным), потому что в самом действии заложена смена «жесткости» данных!

Давайте разберем, как решить эту дилемму, чтобы компилятор в 4 Кб памяти работал без сбоев.

------

Почему `port 1masеka "Wait"` — это ОШИБКА для компилятора

Если мы разрешим форму `maseka`, где внутри одного суффикса смешиваются **A** и **E**, мы нарушим главный принцип микро-парсера на ассемблере x86.

Чтобы уместиться в 4 Кб, наш компилятор должен быть «ленивым». Он не должен читать слово целиком. Он находит суффикс и смотрит **только на его последнюю гласную**, чтобы понять тип операции:

- Если на конце **`A`** (`-masaka`) → компилятор сразу переключает процессор в режим работы с **числами**.
- Если на конце **`E`** (`-meseke`) → компилятор переключает процессор в режим работы со **строками**.

Если мы напишем `port 1maseka "Wait"`, ленивый компилятор посмотрит на последнюю букву `A` в суффиксе `-maseka` и подумает: *«Ага, на конце А, значит я должен применить операцию к двум числам!»*. Он попытается сложить или сравнить порт с числовым адресом строки, вместо того чтобы вывести текст. Программа упадет в DOS.

------

Как это решается по закону строгого сингармонизма

В татарском языке (как и в нашем программировании) **корень всегда диктует правила суффиксу**. Что является корнем в нашей строке? Переменная, которую мы проверяем!

1. Если мы проверяем **число** (`port`), то суффикс ОБЯЗАН быть полностью твердым: **`-masaka`**. Тот факт, что выводится строка `"Wait"`, процессору не важен — само ветвление логики происходит на основе числа.
2. Если мы проверяем **строку/клавишу** (`key`), то суффикс ОБЯЗАН быть полностью мягким: **`-meseke`**.

Единственно правильный строгий вариант:

- Числовое условие: `port 1masaka "Wait"` (Суффикс твердый, так как `port` — число).
- Строковое условие: `key 'q'meseke "Wait"` (Суффикс мягкий, так как `key` — символ).

При таком подходе компилятор на ассемблере x86 займет минимум места. Он прочитает имя `port`, увидит, что оно твердое, затем проверит суффикс, увидит на конце `A` (`-masaka`) — всё совпало, гармония соблюдена, код компилируется в 1 байт.

Таблица сложных слитных суффиксов (Комбинаторика)

| Исходные суффиксы                                        | Твёрдая форма сочетания | Мягкая форма сочетания | Смысл операции (Что заменяет в Basic / Си) | Пример использования и перевод                               |
| -------------------------------------------------------- | ----------------------- | ---------------------- | ------------------------------------------ | ------------------------------------------------------------ |
| **Условие + Переход**   *(Conditionalis + Dativus)*      | **-saga**               | **-sege**              | `IF (==) THEN GOTO`                        | `port 255saga quit` *(Если порт равен 255, то прыгнуть на quit)* |

| **Условие + Ввод**   *(Conditionalis + Ablativus)*       | **-sadan**              | **-seden**             | `IF (==) THEN PEEK / READ`                 | `status 1sadan 96` *(Если статус 1, то считать данные ИЗ порта 96)* |

| **Отриц. цикл + Переход**   *(Neg. + Prolativus + Dat.)* | **-masgancaga**         | **-mesgencege**        | `UNTIL / WHILE NOT`                        | `status 1masgancaga wait` *(Пока статус НЕ равен 1, прыгать на 'wait')* |

Архитектурные правила сборки сочетаний:

1. **Закон доминирования первой гласной:** Как видно из таблицы, в твёрдой форме промежуточные условные или циклические элементы (`-se-`, `-gence-`) насильно превращаются в полностью твердые (`-sa-`, `-ganca-`). В мягкой — наоборот. Компилятор x86 проверяет только **последний байт суффикса** (букву `A` или `E`), чтобы выбрать математику обработки (регистры или строки).
2. **Усечение согласных для лаконичности:** При физической склейке суффиксов (например, `-mas` + `-sa` + `-ka`) промежуточные согласные стягиваются (`-massaka` \(\rightarrow \) **`-masaka`**), чтобы экономить буквы в исходном коде и упростить токенизацию.
3. **Экономия на служебных словах:** Каждая строка этой таблицы — готовая управляющая конструкция. Программисту не нужно использовать маркеры начала и конца блоков, парсеру не нужно считать вложенность строк. Программа исполняется строго линейно, как в ассемблере x86.

Как это работает на примере сложной фразы

Давайте возьмем живую татарскую фразу и посмотрим, как она превращается в ультра-компактный код Способа 3 (Слияние условия и действия), который мы утвердили:

- **Фраза на татарском:** *«Ключ булмаса, өйгә кайт»*
- **Перевод на русский:** «Если ключа нет, вернись домой».

2. `0` — значение (отсутствие/ноль).

Вся тяжелая логика со скобками и операторами `IF NOT == THEN GOTO` выражена так же лаконично и естественно, как говорят люди.

**Ключевая идея:** модули содержат **машинный код**, который загружается в память и **встраивается в таблицу операторов**. Вызов происходит **как встроенный оператор**, без накладных расходов.

## 2. Таблица операторов (Jump Table)

В ядре Älifba есть **таблица указателей** на код каждого оператора:

````
; Ядро Älifba - таблица операторов
op_table:
    dw print_handler      ; 0x00: PRINT
    dw input_handler      ; 0x01: INPUT
    dw if_handler         ; 0x02: IF (-sa)
    dw loop_handler       ; 0x03: LOOP (-gança)
    dw assign_handler     ; 0x04: = (присваивание)
    dw goto_handler       ; 0x05: GOTO
    ; ... базовые операторы
    
    ; Расширяемая часть (изначально пустая)
    dw 0                  ; 0x10: свободно
    dw 0                  ; 0x11: свободно
    dw 0                  ; 0x12: свободно
    ; ... до 0xFF
    
op_names:
    db 'print', 0
    db 'input', 0
    db 'sa', 0
    db 'gança', 0
    db '=', 0
    db 'goto', 0
    ; ... базовые имена
    
    ; Расширяемая часть
    db 0, 0               ; 0x10: свободно
    db 0, 0               ; 0x11: свободно
````

**Размер таблицы:** 256 операторов × 2 байта = 512 байт **Имена:** ~200 байт

**Итого: ~700 байт** на таблицу операторов.

## 3. Формат модуля расширения (.alf)

Модуль — это **бинарный файл** с заголовком:

````
; Формат модуля Älifba (math.alf)

; Заголовок (16 байт)
db 'ALF1'              ; сигнатура
dw 2                   ; версия формата
dw 3                   ; количество операторов
dw math_code_start     ; смещение кода
dw math_names_start    ; смещение имён

;   dw имя_смещение    ; указатель на имя
;   dw код_смещение    ; указатель на код
;   db приоритет       ; приоритет (0-255)

; Имена операторов
math_names_start:
    db 'lira', 0        ; 5 байт
    db 'poli', 0        ; 5 байт
    db 'dtrm', 0        ; 5 байт

; Код операторов
math_code_start:
lira_handler:
    ; Алгоритм Гаусса (~500 байт)
    ; Работает напрямую с памятью
    ; ...
    ret

poli_handler:
    ; Схема Горнера (~100 байт)
    ret

dtrm_handler:

## 4. Загрузка модуля интерпретатором

Когда интерпретатор видит `INCLUDE 'math.alf'`, он делает:

````
; Псевдокод интерпретатора Älifba

execute_statement:
    ; Лексер распознал слово "lira"
    ; Ищем его в таблице операторов
    lea si, op_names
    call find_operator   ; возвращает индекс в AX
    
    ; Проверяем, найден ли оператор
    cmp ax, 0xFF
    je unknown_operator
    
    ; Вызываем оператор по таблице переходов
    shl ax, 1            ; * 2 (размер указателя)
    mov bx, [op_table + ax]
    call bx              ; ПРЯМОЙ вызов кода оператора
    
    ret
````

## 5. Вызов оператора из модуля

Когда программа вызывает `lira`, интерпретатор делает:

````
; Псевдокод интерпретатора Älifba

execute_statement:

    ; Ищем его в таблице операторов

**Что происходит при вызове `lira`:**

````
; Вызов lira из программы Älifba
X = lira(A, B)

; Интерпретатор:
1. Лексер читает "lira"
2. Ищет в op_names -> находит индекс 0x10
3. Берёт указатель из op_table[0x10]
4. Делает call lira_handler
5. lira_handler работает напрямую с памятью
6. Результат уже в X
````

**ремя вызова: ~15-20 тактов**

**Это точно так же быстро, как встроенный оператор!**

## 6. Пример расширения: math.alf

Полный код модуля на ассемблере:

````
; math.alf - математические операторы Älifba

; Заголовок
header:
    db 'ALF1'            ; сигнатура
    dw 1                 ; версия
    dw 3                 ; 3 оператора
    dw op_table_start    ; таблица операторов
    dw names_start       ; имена

; Таблица операторов модуля
op_table_start:
    dw name_lira, lira_code, 0   ; lira, приоритет 0
    dw name_poli, poli_code, 0   ; poli, приоритет 0
    dw name_dtrm, dtrm_code, 0   ; dtrm, приоритет 0

; Имена операторов
names_start:
name_lira: db 'lira', 0
name_poli: db 'poli', 0
name_dtrm: db 'dtrm', 0

; Код оператора LIRA
lira_code:
    ; Пролог
    push bp
    mov bp, sp
    push si
    push di
    push ds
    push es
    
    ; Параметры из стека (указатели на массивы)
    mov si, [bp+4]       ; A_ptr
    mov di, [bp+6]       ; B_ptr
    mov bx, [bp+8]       ; X_ptr
    mov cx, [bp+10]      ; N
    
    ; Алгоритм Гаусса с pivoting
    ; ... (500 байт кода)
    
    ; Эпилог
    pop es
    pop ds
    pop di
    pop si
    pop bp
    ret 8                ; очистка стека

; Код оператора POLI
poli_code:
    ; Схема Горнера
    ; ... (100 байт кода)
    ret

; Код оператора DTRM
dtrm_code:
    ; Определитель матрицы
    ; ... (300 байт кода)
    ret
````

**Размер math.alf:** ~1 КБ

## 8. Сравнение: операторы vs функции vs модули



| Подход                       | Вызов                | Время        | Модульность | Сложность |
| ---------------------------- | -------------------- | ------------ | ----------- | --------- |
| **Оператор** (Эллочка)       | `LIRA A;B;X;N`       | ~20 тактов   | ❌ Нет       | Низкая    |
| **Функция** (копирование)    | `X = lira_slow(A,B)` | ~5000 тактов | ✅ Да        | Низкая    |
| **Функция** (указатели)      | `X = lira(A,B)`      | ~25 тактов   | ✅ Да        | Средняя   |
| **Модуль-оператор** (Älifba) | `X = lira(A,B)`      | ~20 тактов   | ✅ Да        | Высокая   |

**Вывод:** модули-операторы дают **лучшее из двух миров**:

- Производительность оператора (20 тактов)
- Модульность функции (можно добавлять новые операторы)

## 9. Преимущества модульной архитектуры Älifba

### 1. Расширяемость без перекомпиляции

Пользователи могут писать свои операторы:

````
; graphics.alf - пользовательский модуль
db 'ALF1'
dw 1
dw 2
dw op_table, names

op_table:
    dw name_pixel, pixel_code, 0
    dw name_line, line_code, 0

names:
name_pixel: db 'pixel', 0
name_line: db 'line', 0

pixel_code:
    ; Рисование пикселя
    ret

line_code:
    ; Рисование линии
    ret
````

Добавляем в программу:

````
INCLUDE 'graphics.alf'
100 100 pixel
````

**Интерпретатор не нужно перекомпилировать!**

### 2. Распределение кода

Можно делать **пакеты операторов**:

- `math.alf` — математика
- `graphics.alf` — графика
- `network.alf` — сеть
- `crypto.alf` — шифрование
- `gui.alf` — интерфейс

Каждый пакет — отдельный файл ~1-2 КБ.

### 3. Обновление без перекомпиляции ядра

Если нашли баг в `lira`, просто заменяем `math.alf` на новую версию. Ядро не трогаем.

## 10. Технические ограничения

### Размер памяти

В DOS COM-файле всего **64 КБ** на всё:

````
Ядро Älifba:        3 КБ
Таблица операторов: 1 КБ
Модули:             ~5 КБ (2-3 модуля)
Данные программы:   ~50 КБ
Стек:               ~5 КБ
````

**Максимум:** 5-6 модулей по 1 КБ каждый.

### Скорость загрузки

Загрузка модуля — это **файловый ввод-вывод** (~50-100 мс).

**Решение:** загружаем модули **один раз при старте**, дальше работаем с памятью.

### Безопасность

Модуль содержит **машинный код**, который может делать что угодно.

**Решение:** в DOS нет защиты памяти, так что это не проблема. Но в современных системах нужна песочница.

## 12. Главная мысль

**Эллочка:** 62 оператора встроены в интерпретатор. Добавить новый оператор — перекомпилировать интерпретатор.

**Älifba:** базовые операторы в ядре, специфичные — в модулях. Добавить новый оператор — написать файл `myop.alf` и добавить `INCLUDE 'myop.alf'`.

**Производительность:** одинаковая (~20 тактов на вызов).

**Модульность:** Älifba выигрывает.

**Расширяемость:** Älifba выигрывает.

**Сложность реализации:** Älifba чуть сложнее (нужен загрузчик модулей), но это **однократная работа**.
